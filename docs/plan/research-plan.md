## Introduction

Vehicular crowdsensing systems reward vehicles for reporting traffic and environmental data, which makes them a target for **Sybil attacks**: one adversary forges many vehicle identities to inject fabricated Basic Safety Messages and claim unearned rewards. Forged messages often look locally plausible — position, speed, and heading fall in realistic ranges at each time step — while the fabrication only shows up as replay artifacts, temporal discontinuities, or physically unrealistic motion over longer windows.

This plan operationalizes the thesis proposal into six executable phases. The approach: pretrain a compact **Transformer encoder-decoder** on unlabeled VeReMi trajectory windows using two self-supervised objectives — **Masked Trajectory Reconstruction (MTR)** and **Trajectory Consistency Prediction (TCP)** over synthetic corruptions (replay, local shuffle, speed-scale, position-offset) — then discard the decoder and evaluate the encoder on Sybil detection. Because VeReMi is generated by SUMO on a real urban road network (Luxembourg scenario), the representations are *implicitly road-network-grounded* without needing an explicit road graph or map-matching.

### Research question

> Does a self-supervised trajectory foundation model trained on road-network-grounded vehicular message traces produce representations that improve Sybil detection relative to supervised-only baselines, particularly under few-shot supervision and scenario-holdout evaluation?

### Hypotheses

| ID | Hypothesis | Tested in |

### ⚠ GridSybil_0709 windowing defect (found during Phase 1, blocks a Phase 2 acceptance criterion)

**`scripts/prepare_data.py` (task 2.6) must fix this before regenerating `data/prepared_data/`.** The current
windowing code groups ground-truth messages by `senderPseudo`, but in `GridSybil_0709` the value
`senderPseudo == 1` is a shared sentinel across **653 different physical vehicles** (71,767 GT messages). Windowing
therefore splices unrelated vehicles' messages together by timestamp order, producing **14,764 windows (5.16% of
the entire 285,926-window dataset)** with physically meaningless `dt`/`dpos`/`dspd` values. Scoped entirely to
`GridSybil_0709` (both subfolders) — `GridSybil_1416` and every other family/group are unaffected. Full detail,
evidence, and the required fix (group by raw `sender`/`node_id`, not `senderPseudo`) are in
`docs/research-notes/data_understanding/gridsybil-windowing-defect.md`. Any number computed from the current `X_windows.npy` for
GridSybil_0709 (including the v1 pilot results in `models/results/`) carries this caveat until task 2.6 fixes it.

### Known risks

- **Class imbalance:** benign windows dominate; attack families differ in size across groups (0709 ≈ 2× the windows of 1416, now quantified as 2.16:1 — see class-balance.md). Unweighted training and accuracy-style metrics would mislead — mitigate with per-class metrics (macro-F1, per-family recall) and, if needed, class-weighted losses.
- **Per-scenario leakage via sender pseudonyms:** the same underlying vehicle contributes many overlapping windows; pseudonym reuse within a scenario means naive random window splits leak near-duplicates across train/test. All splits must be assigned at the sender-sequence level *before* window generation — verified for the existing `idx_*` files (task 1.5, `scripts/audit_splits.py`, all pass).
- **Simulator regularity:** SUMO traces are smoother than real telemetry; the model may key on simulation artifacts. Note as a limitation (Phase 6) and keep the noise-variant fields in reserve for a robustness check.
- **Windowing groupby key bug (new, see above):** `senderPseudo` is not a reliable per-vehicle key across the whole dataset — confirmed to break down specifically in `GridSybil_0709`. Must be fixed at the source (task 2.6) rather than patched downstream.

### Design notes — corruption parameters (decisions to make)

These are the knobs for the Trajectory Consistency Prediction (TCP) pretext task. Each needs a chosen range, justified against the EDA statistics, before pretraining runs:

- **Replay**: how far back to sample the replayed segment (same sender vs different sender; same scenario vs cross-scenario). Cross-sender replay most closely mimics `DataReplaySybil` — decide whether that overlap with the downstream label is a feature (task-aligned pretraining) or a leakage risk to document.
- **Shuffle**: permute all T=20 steps vs shuffle within sub-blocks (e.g. blocks of 5). Full shuffles may be too easy for the model; block shuffles preserve local smoothness and are harder.
- **Speed-scale**: multiplicative factor range on `spd_x/y` (and consistently on `dspd`, `dpos`). Candidate range 0.5×–2.0×; benign mean speed is ~10.2 m/s, so scales beyond ~2× leave the physically-plausible envelope and become trivially detectable.
- **Positional-offset**: additive offset magnitude on `pos_x/y` (and `dpos` at the corruption boundary). Candidate range 10–100 m; the map spans roughly ±1 km (pos std ≈ 335–421 m), so offsets ≫100 m teleport off-road and make the task trivial, offsets ≪10 m hide inside GPS-like noise.
- **Consistency of derived features**: every corruption must keep the derived deltas (`dt`, `dpos`, `dspd`) consistent with the corrupted primaries — recompute deltas after corrupting, never corrupt primaries and deltas independently.
- **Per-window corruption sampling**: probability of applying each corruption type per pretraining sample (uniform over the 4 types vs weighted), and whether "clean" (no corruption) is a 5th class for TCP. Recommend: uniform 4-way + clean class, revisit in the Phase 5 ablation.

## Phase 3 — Methodology

RoadFM-Lite is an encoder–decoder foundation model pretrained on unlabeled trajectory windows with two objectives — masked trajectory reconstruction (MTR) and trajectory consistency prediction (TCP) — after which the decoder is discarded and only the encoder transfers to downstream Sybil detection (few-shot contrastive, linear-probe, and zero-shot retrieval heads). A v1 exists in `models/transformer_model.ipynb` with checkpoints `models/roadfm_lite_pretrained.pt` / `models/roadfm_lite_final.pt`; this phase hardens that prototype into the thesis-grade method.

**Acceptance criteria**

- **3.1** — The thesis architecture section matches the running code exactly: input_dim=13, d_model=128, nhead=8, num_layers=6 (encoder and decoder), dim_feedforward=512, dropout=0.1, sinusoidal positional encoding, mean-pooled window embedding, learned mask token with cross-attention decoder. - **3.2** — MTR masks a fraction of timesteps (currently mask_ratio=0.15), the decoder reconstructs masked feature vectors via cross-attention, and the loss is mean L2 over masked positions only. A unit test verifies loss is computed on masked positions and gradients reach the encoder.
- **3.3** — All four non-identity corruption operators are implemented and applied at pretraining time with corruption-class labels feeding the 5-way TCP softmax head. *Current v1 trains TCP only on identity (label 0) — the corruption operators are the main outstanding methodology work.* Each operator has a visual sanity-check figure (original vs. corrupted window).
- **3.4** — The pretraining loss is L = λ₁·L_MTR + λ₂·L_TCP (v1 uses λ₁=1.0, λ₂=0.5 untuned). A small sweep (e.g. λ₂ ∈ {0.1, 0.5, 1.0}) justifies the final weighting, judged on downstream validation F1, not pretraining loss.
- **3.5** — Both a binary (benign vs. Sybil) head and a 5-class (benign + 4 attack families) head run on frozen and fine-tuned encoder embeddings; the few-shot path uses supervised-contrastive (InfoNCE) fine-tuning followed by a linear classifier, per the proposal.
