Embedding

Each 13-number row becomes a 128-number row, so the window goes from 64 × 13 to 64 × 128.

64 × 13 → 64 × 128 → 64 × 128 → X⁽⁰⁾: 64 × 128

Token embedding, then add position, then multiply by the mask.

Token embedding (Conv1d, kernel 3)

For each row t, look at the row before, the row itself and the row after. Rows outside 1…64 count as 0. There is no bias.

e_t = W₋₁ · x_{t−1} + W₀ · x_t + W₊₁ · x_{t+1}
each W128 × 13
each x13 × 1
each e_t128 × 1
all 64 rows stacked64 × 128
weights 128 × 13 × 3 = 4,992
Transformer view
  • Conv1d with kernel 3 is exactly a Linear(39 → 128) applied to the concatenation [xt−1; xt; xt+1] (3 × 13 = 39), the same weights at every t: Wcat = [W₋₁ W₀ W₊₁] is 128 × 39.
  • So it is a token embedding that already sees one neighbour on each side. With kernel 1 it would be the plain per-token Linear(13 → 128) you know.
  • Positions are added exactly like in the original Transformer (sin/cos, not learned).

class TokenEmbedding(nn.Module):
    def __init__(self, n_features=13, d_model=128, dropout=0.1, max_len=512):
        super().__init__()
        # weight: (128, 13, 3) = 4,992 params, no bias; zero padding (not circular)
        self.conv = nn.Conv1d(n_features, d_model, kernel_size=3, padding=1,
                              padding_mode="zeros", bias=False)
        self.dropout = nn.Dropout(dropout)
        pos = torch.arange(max_len).unsqueeze(1).float()                     # (512, 1)
        div = torch.exp(torch.arange(0, d_model, 2).float()
                        * (-math.log(10000.0) / d_model))                    # (64,)
        table = torch.zeros(max_len, d_model)                                # (512, 128)
        table[:, 0::2] = torch.sin(pos * div)
        table[:, 1::2] = torch.cos(pos * div)
        self.register_buffer("positions", table, persistent=False)          # fixed, 0 params

    def forward(self, x, mask):                       # x: (B, 64, 13), mask: (B, 64)
        t = self.conv(x.transpose(1, 2))             # (B, 13, 64) -> conv -> (B, 128, 64)
        t = t.transpose(1, 2)                        # (B, 64, 128)   e_t for every row t
        out = self.dropout(t + self.positions[:x.shape[1]])  # + (64, 128) broadcast -> (B, 64, 128)
        return out * mask.unsqueeze(-1)              # (B, 64, 1) mask -> padding rows = 0

Inside one TimesBlock

A TimesBlock takes a 64 × 128 matrix, finds repeating periods, folds time into a 2-D grid, convolves it, and gives back 64 × 128 again.

64 × 128→128 × 5 × 14→128 × 5 × 14→128 × 5 × 14→64 × 128

The flow shows one period (p = 14). The block does this for 3 periods, then mixes them. There are 4 blocks, one after another.

Transformer view: what replaces attention
  • Attention mixes token t with every token, with weights computed from the content (QKᵀ, 64 × 64).
  • A TimesBlock mixes token t with a fixed pattern: its neighbours and the tokens exactly one or two periods away (diagram). The weights are learned conv kernels, not computed per input.
  • The input-dependent part is which periods are used (FFT per window) and how the 3 period-branches are weighted (softmax of FFT amplitudes) — like choosing 3 attention patterns per window.
  • Stacking 4 blocks widens the reach, like stacking layers of local attention.
  • Cost: no 64 × 64 attention matrix; the price is weaker long-range, content-based mixing.

Find periods

Run an FFT along time over the 28 real rows only. Padding is left out.

real rows of X28 × 128
FFT along time: 15 frequencies (0…14)15 × 128

p = 28 // f → 14, 7, 5 (amplitudes ≈ 2.02, 1.56, 1.42)
PyTorch · finding the periods (FFT on real rows)
def find_periods(h, mask, top_k=3, min_freq=2):      # h: (B, 64, 128), mask: (B, 64)
    n_real = mask.sum(1)                              # (B,)  e.g. tensor([28])
    periods = torch.ones(h.shape[0], top_k, dtype=torch.long)   # (B, 3), default period 1
    weights = torch.zeros(h.shape[0], top_k)                    # (B, 3)
    for n in n_real.unique().tolist():                # windows with the same length together
        rows = (n_real == n).nonzero().squeeze(1)
        amp = torch.fft.rfft(h[rows, :n], dim=1)      # real rows only: (b, 28, 128) -> (b, 15, 128) complex
        amp = amp.abs().mean(-1)                      # average over channels -> (b, 15)
        amp[:, :min_freq] = float("-inf")             # skip f = 0 (mean) and f = 1 (whole window)
        k = min(top_k, amp.shape[1] - min_freq)
        if k <= 0:
            continue                                  # < 4 real rows: keep period 1
        top_amp, top_f = amp.topk(k, dim=1)           # (b, 3): f = 2, 4, 5
        periods[rows, :k] = n // top_f                # 28 // f -> 14, 7, 5
        weights[rows, :k] = top_amp                   # ~2.02, 1.56, 1.42
    return periods, weights                           # (B, 3), (B, 3)

2-D convolution (Inception)

Inception = three Conv2d in parallel (1×1, 3×3, 5×5, "same" padding). Their outputs are averaged, so the grid size does not change.

Inception(128 → 64) → GELU → Inception(64 → 128)
input grid (p = 14)128 × 5 × 14
after first Inception + GELU64 × 5 × 14
after second Inception128 × 5 × 14
first 64 × 128 × (1 + 9 + 25) + 3 × 64 = 286,912
second 128 × 64 × 35 + 3 × 128 = 287,104
one block = 574,016
Transformer viewInception(128→64) → GELU → Inception(64→128) plays the role of the FFN (Linear d→4d → GELU → Linear 4d→d). Two differences: it is a convolution over the folded grid, so it also mixes tokens (an FFN is per-token), and its inner width shrinks to d_ff = 64 (half of d = 128) instead of expanding to 512 (4d); the block has 574,016 parameters.
PyTorch · Inception block
class InceptionBlock2d(nn.Module):                    # from THUML Time-Series-Library (MIT)
    def __init__(self, c_in, c_out, n_kernels=3):
        super().__init__()
        self.kernels = nn.ModuleList(                 # kernel 1x1, 3x3, 5x5, "same" padding
            nn.Conv2d(c_in, c_out, kernel_size=2 * i + 1, padding=i) for i in range(n_kernels))

    def forward(self, x):                             # x: (b, C_in, cycles, p)    e.g. (1, 128, 5, 14)
        outs = [conv(x) for conv in self.kernels]     # 3 x (b, C_out, cycles, p)   e.g. 3 x (1, 64, 5, 14)
        return torch.stack(outs, -1).mean(-1)         # average, not concat -> (1, 64, 5, 14)

# params: Inception(128 -> 64) = 64*128*(1+9+25) + 3*64 = 286,912; Inception(64 -> 128) = 128*64*35 + 3*128 = 287,104

PyTorch · one TimesBlock: fold → conv → unfold → mix → residual → mask
class TimesBlock(nn.Module):
    def __init__(self, d_model=128, d_ff=64, top_k=3):
        super().__init__()
        self.top_k = top_k
        self.conv = nn.Sequential(InceptionBlock2d(d_model, d_ff), nn.GELU(),
                                  InceptionBlock2d(d_ff, d_model))   # 574,016 params

    def fold_conv_unfold(self, x, p):                 # x: (b, 64, 128), p = 14
        b, T, d = x.shape
        T_pad = math.ceil(T / p) * p                  # 70
        x = torch.cat([x, x.new_zeros(b, T_pad - T, d)], dim=1)       # (b, 70, 128)
        grid = x.reshape(b, T_pad // p, p, d)         # (b, 5, 14, 128)   cycles x position
        grid = grid.permute(0, 3, 1, 2)               # (b, 128, 5, 14)   channels first for Conv2d
        grid = self.conv(grid)                        # (b, 128, 5, 14)
        out = grid.permute(0, 2, 3, 1).reshape(b, T_pad, d)            # (b, 70, 128)
        return out[:, :T]                             # (b, 64, 128)

    def forward(self, x, mask):                       # x: (B, 64, 128), mask: (B, 64)
        periods, weights = find_periods(x, mask, self.top_k)          # (B, 3), (B, 3)
        branches = []
        for slot in range(self.top_k):                # 3 branches: p = 14, 7, 5 for our window
            out = torch.zeros_like(x)                 # (B, 64, 128)
            for p in periods[:, slot].unique().tolist():
                idx = (periods[:, slot] == p).nonzero(as_tuple=True)[0]
                out[idx] = self.fold_conv_unfold(x[idx], int(p))
            branches.append(out)
        stacked = torch.stack(branches, dim=-1)       # (B, 64, 128, 3)
        w = F.softmax(weights, dim=1)[:, None, None, :]               # (B, 1, 1, 3) ~ 0.46, 0.29, 0.25
        out = (stacked * w).sum(-1) + x               # weighted sum + residual -> (B, 64, 128)
        return out * mask.unsqueeze(-1)               # padding rows = 0

Output: H and z

After 4 TimesBlocks the encoder gives one vector per message (H) and one vector per window (z).

64 × 128→ H 64 × 128→ 28 × 128→ z 128

H is 64 × 128: one 128-vector for each message. The 36 padding rows of H are 0.

z is the masked mean of H. Only the 28 real rows count.

z = (sum of the 28 real rows of H) ÷ 28

PyTorch · the whole encoder and the masked mean
class TimesNetEncoder(nn.Module):
    def __init__(self, n_blocks=4, d_model=128):
        super().__init__()
        self.embedding = TokenEmbedding()
        self.blocks = nn.ModuleList(TimesBlock() for _ in range(n_blocks))
        self.norm = nn.LayerNorm(d_model)             # one LayerNorm shared by all blocks, 256 params

    def forward(self, x, mask):                       # x: (B, 64, 13), mask: (B, 64)
        keep = mask.unsqueeze(-1).float()             # (B, 64, 1)
        h = self.embedding(x * keep, mask)            # (B, 64, 128)
        for block in self.blocks:                     # 4 times
            h = self.norm(block(h, mask)) * keep      # (B, 64, 128)
        z = (h * keep).sum(1) / keep.sum(1).clamp(min=1)   # masked mean: (B, 128) = sum of 28 rows / 28
        return h, z                                   # H: (B, 64, 128), z: (B, 128)

Embedding: turning 13 numbers per message into 128

Which embedding is used?

Token embedding + positional embedding. This is TimesNet's DataEmbedding with the time-feature (timestamp) part removed.

  • Token embedding: a Conv1d(13 → 128, kernel 3) maps each message's 13 features to 128 numbers.
  • Positional embedding: a fixed sine/cosine table 64 × 128 is added on top.
  • Then dropout (0.1), then × mask.
x 64 × 13 → Conv1d → 64 × 128 → + position table 64 × 128 → dropout → × mask → 64 × 128
What does the Conv1d embedding do, in simple words?

For every message t it looks at three messages: the one before, itself and the one after. It multiplies each by its own weight matrix (128 × 13) and adds the three results. The output is one 128-number vector for message t.

e(t) = W₋₁·x(t−1) + W₀·x(t) + W₊₁·x(t+1)

It is the same as gluing the 3 messages into one 39-number vector and applying Linear(39 → 128). The same weights are used at every position. There is no bias, so it has 3 × 13 × 128 = 4,992 weights.

Why kernel 3 and not 1?

Kernel 1 would embed each message alone, like a plain Linear(13 → 128). Kernel 3 lets each vector also see its neighbours one second before and after. So a change between messages, such as a speed jump, already shows up in the embedding. It costs little: 4,992 weights instead of 1,664.

Why add a position table, and why not a learned one?

The convolution uses the same weights at every position, so on its own it cannot tell message 3 from message 40. Adding a different 128-number pattern for each of the 64 positions gives every row a "where am I" signal.

The table uses the same sine/cosine formula as the original Transformer. It is fixed, so it has 0 parameters and nothing to train. A learned table would add 64 × 128 = 8,192 more numbers to fit.

Why no time-of-day embedding?

TimesNet normally also embeds the timestamp (hour, minute, …). We leave it out because the time of day alone tells the two scenario groups apart (0709 vs 1416). The model could use the clock as a shortcut instead of learning how vehicles move. The only time information it gets is the message order and the gap between messages (the log-Δτ feature).

Why zero padding, not circular?

A kernel of 3 needs a neighbour before row 0 and after row 63. TimesNet's default circular padding takes the missing neighbour from the other end, so row 0 would see row 63. In our windows the last rows are usually padding: in the worked window rows 28–63 are padding. Circular padding would mix that padding into row 0. Zero padding puts a row of zeros there instead.

Why multiply by the mask after the embedding?

After the embedding, padding rows are no longer zero. The position table adds a sine/cosine pattern to every row, and the convolution at row 28 can see real row 27. Multiplying by the mask (1 = real, 0 = padding) sets those rows back to exactly zero.

worked window: rows 0–27 × 1 (kept), rows 28–63 × 0 → 64 × 128 with 36 zero rows

The same masking is repeated after every TimesBlock, so padding can never pass anything on to the real rows.

Inception and convolution

What is an Inception block?

It is a small layer made of three 2-D convolutions that run side by side on the same input: kernel 1×1, 3×3 and 5×5. Their outputs are averaged into one result.

The code comes from the THUML Time-Series-Library. The idea comes from GoogLeNet's "Inception" (Szegedy, 2015).

In TimesNet it works on the folded grid. For period 14, that grid is 128 × 5 × 14 (channels × cycles × position in the cycle).

How does it work, in simple words?
  • The same grid goes into all three convolutions at once.
  • Each one uses "same" padding, so each output grid has the same size as the input (5 × 14 stays 5 × 14).
  • Because the three outputs have the same shape, they can be added up cell by cell and divided by 3.

A TimesBlock uses two of these in a row for each period: Inception(128 → 64) → GELU → Inception(64 → 128).

Why three kernel sizes?

We don't know in advance whether a short pattern or a wider one matters. So the model gets all three and learns its own weights for each.

  • 1×1: only the cell itself. It mixes the channels and looks at no neighbours.
  • 3×3: the cell plus 1 step in every direction (9 cells).
  • 5×5: the cell plus 2 steps in every direction (25 cells).

Example with period 7: for message 17, the 3×3 kernel sees messages 9–11, 16–18 and 23–25.

What do "horizontal" and "vertical" mean in the folded grid?

Folding cuts the 64 rows into cycles of length p and stacks the cycles on top of each other.

  • Horizontal = the next or previous message in the same cycle (t ± 1).
  • Vertical = the same position in the next or previous cycle (t ± p).

Example with p = 14: message 17 is in cycle 1, position 3. Horizontally it touches 16 and 18. Vertically it touches 3 and 31, which are one period away. One 2-D kernel looks at both "just before" and "one cycle ago" at once.

Why 128 → 64 → 128 (bottleneck)?

The first Inception narrows the 128 channels to 64 (d_ff = 64). GELU runs on those 64 channels. The second Inception maps 64 back to 128, so the output can be added to the block input (the residual).

d_ff = 64 is the professor's plan (decision D12). It halves the convolution weights compared with d_ff = 128: 574,016 parameters per block instead of 1,147,648, so the encoder has 2.30M instead of 4.60M parameters. With only ~5.7k sender vehicles to learn from, the smaller model is less likely to overfit, and it trains faster. We watch the pretrain-val loss and the collapse / length monitors; d_ff = 128 is the first ablation if the model underfits (d = 256 / 512 come later, chosen only by evidence).

How many parameters, and why are most of them in the 5×5?

A conv has in × out × k × k weights plus one bias per output channel. Together the three kernels cover 1 + 9 + 25 = 35 cells.

Inception(128→64): 64·128·35 + 3·64 = 286,912
second Inception(64→128): 128·64·35 + 3·128 = 287,104
per TimesBlock: 574,016 × 4 blocks = 2,296,064

The 5×5 kernel has 25 of those 35 cells, so it holds about 71% of the weights (204,800 of 286,720 in one Inception). The 1×1 holds only 8,192. The 4 blocks make up almost all of the encoder's 2,301,312 parameters.

Is this the same as GoogLeNet's Inception?

Same idea, simpler version. There are two differences:

  • Averaged, not concatenated. GoogLeNet stacks the branch outputs along the channel axis, so the channel count grows. Here the three outputs are averaged, so the output keeps the channel count we asked for (128 here).
  • No pooling branch. GoogLeNet also has a max-pooling branch. Here there are only the three convolutions.

The rest of the encoder — "how" questions

How does the FFT find the periods?

The FFT rewrites a sequence as a sum of waves and tells how strong each wave is. It runs over the real rows only: 28 × 128 gives 15 frequencies per channel. The amplitudes are averaged over the 128 channels, f = 0 (the plain average) and f = 1 (one wave over the whole window) are skipped, and the 3 strongest are kept.

top-3 frequencies: f = 2, 4, 5 (amplitudes ≈ 2.02, 1.56, 1.42)period = 28 // f → 14, 7, 5 messages

Each block does this again on its own input, so periods can change (window 0: [14, 7, 5] in block 0, [14, 7, 9] later). With fewer than 4 real rows the period is 1.

How does folding work?

Folding turns the 1-D sequence into a 2-D grid so that a 2-D convolution can see two kinds of neighbours at once. For period p = 14, the 64 rows are padded to 70 (= 5 × 14) and reshaped: each row of the grid is one cycle of 14 messages.

64 × 128 → pad → 70 × 128 → reshape → 128 × 5 × 14(channels × cycles × position in cycle)

After the Inception convolutions the grid is unfolded back to 70 × 128 and cut to 64 × 128.

How are the 3 periods combined?

Each period gives its own branch output of size 64 × 128. They are mixed with weights from a softmax over the FFT amplitudes, so the strongest period counts most.

softmax(2.02, 1.56, 1.42) ≈ 0.46, 0.29, 0.25out = 0.46·branch(14) + 0.29·branch(7) + 0.25·branch(5)

Then the block input is added back (residual), padding rows are zeroed (× mask), a LayerNorm normalises the 128 numbers of each row, and the mask is applied again.

How does the mask stop padding from mattering?
  • Padding rows are set to 0 after the embedding and after every block.
  • The FFT looks only at the real rows (28, not 64).
  • z averages only real rows, and the losses count only real rows.

Check: putting garbage values into the 36 padding rows of the worked window changes the output by exactly 0.

How is z made, and why not a [CLS] token?

z is the average of the real rows of H: sum the 28 real vectors and divide by 28, giving one 128 vector per window. Dividing by 64 would shrink z by 28/64 ≈ 0.44 and tell the model how long the window is, which is a shortcut, not a motion pattern.

A [CLS] token works in a Transformer because attention lets that one token read every row. TimesNet has no attention: its convolutions only see nearby cells, and an extra fake row would also be counted in the FFT and folded into the grid. Averaging gives every real message an equal say.

How will the heads train the encoder without labels?

Each head sets a puzzle whose answer comes from the data itself, never from attack labels:

  • Reconstruction (on H): hide 25% of real rows (7 of 28) and predict their 13 features; MSE on the hidden rows.
  • P1 / P2 / P3 (on z): we inject a speed jump, a scaled speed or a sharp turn into half the windows; each head says yes / no.
  • Contrastive (on z, via a 128 → 128 → 128 projection): two altered views of the same window are pulled close, other windows pushed apart (NT-Xent, τ = 0.1).

To solve these, the encoder has to learn what normal motion looks like. Training has not been run yet.

What is used after pretraining?

Only the encoder (2,301,312 parameters) is kept; all pretraining heads are dropped. Its window vector z (128) becomes the input for few-shot Sybil detection with a handful of labelled windows, and for an anomaly score that compares a window with unlabelled ones.
