Summary

yes

Did self-supervised pretraining learn its pretext tasks?

Yes, on the label-free check set: val_joint fell 2.151 -> 0.377; masked reconstruction 0.173 vs 0.392 for linear interpolation (13 / 13 features better); injected-violation heads reach AUROC P1 0.986, P2 0.998, P3 0.997 (from ~0.5); no collapse (effective rank of z 48.0 -> 75.5 of 128).

no

Is the run finished (converged, schedule as configured)?

No. val_joint still fell 2.9% in the last epoch (best = last epoch), and the cosine LR schedule ended at 80% of peak (7.99e-4) instead of ~0 because of a scheduler bug in train.py.

partly

How much of the data actually trained the model?

Little: 70.1% of train windows have 1 real row and carry no loss, so ~70.2% of the 179,420 batches were skipped; ~13.7% of batches trained reconstruction only (2-3 rows) and ~16.2% trained all five losses (>= 4 rows).

no

Does the frozen encoder flag Sybil attacks without labels (kNN anomaly score, test group 1416)?

Only GridSybil, weakly: AUROC 0.613 vs 0.525 for window length alone. DataReplay 0.337, DoSRandom 0.144, DoSDisruptive 0.307 are below chance, while length alone gives 0.950 / 0.965 / 0.965. Benign FPR at the untuned threshold is 0.121 (nominal 0.05).

pending

Does pretraining beat a TimesNet that was not pretrained?

Not known yet: the frozen-probe evaluation with the random-init, length-only and simple-statistics controls (npm run eval:all) has not been run on the real checkpoint.

no

Can these numbers support a thesis claim?

Not yet: one seed, one run with a known schedule bug, test restricted to group 1416 (F14), no validation split for thresholds (D8'), and no from-scratch control.

Still pending

  • Frozen-encoder evaluation (npm run eval:all -> src/runs/evaluation/all/T24/model-all/results.json + report_data.json): probes for model-all vs random-init vs length-only vs simple statistics, 3 seeds, vehicle-bootstrap CI, n <= 3 vs n >= 4.

Health verdicts (from the summariser)

  • look converged? No — val_joint still fell 2.9% in the last epoch (best = last epoch) and the LR was still 80% of peak; more epochs would likely help.
  • ok plateau? Flat (< 3% change over the last 3 epochs): val_recon, val_nce; still moving: val_joint, val_p1, val_p2, val_p3.
  • ok reconstruction beats interpolation? Yes — val_recon 0.1731 vs linear interpolation 0.3919 (ratio 0.44; init 0.8872); 13/13 features beat it.
  • ok physics heads learn? Yes, on their pretext task — AUROC on injected violations (check set) P1 0.489→0.986, P2 0.462→0.998, P3 0.513→0.997. This is detection of violations we inject, not of real attacks.
  • ok embedding collapse? No — effective rank of z 48.0→75.5 (of d = 128), cos_pos − cos_neg 0.93; the least-used dimension's std fell 0.480→0.076 (watch, not collapse).
  • look length encoded in z? Yes, strongly — a ridge probe recovers window length from z with R² 0.986 (init) → 0.876 (final); corr(|z|, length) -0.65. Probes can exploit length (F11).
  • look how much data trains each loss? Thin — ≈70% of batches had no loss (1-row windows, skipped), ≈14% reconstruction only (2–3 rows), ≈16% all five losses (≥ 4 rows). Train shards: 70.1% of windows have 1 row, 13.4% have 2–3.
  • look LR schedule as configured? No — the cosine was meant to reach ≈1.00e-09 by the last logged step but the LR was 7.99e-04 (80% of peak): the scheduler counts only real updates (≈53,468) against a total of 179,420 batches.
  • ok training values finite? Yes — 0 non-finite values in 1075 logged train records (absent losses are omitted, not NaN; a table that pads them with NaN can misreport this).

θ rule: θ = p95 of the scores of 20,000 unlabeled train windows from the run's check-set vehicles (not in the bank, never trained on); no labels used; no val split exists (D8′), so θ is not tuned. score = 1 − mean cosine similarity of z to its 10 nearest bank windows; bank = 60,000 unlabeled train windows of the trained-on vehicles. rank_pct = % of those calibration scores ≤ the window's score.

Diagnosis

I1high

Cosine LR schedule does not decay: the scheduler counts real updates, the horizon counts all batches

  • train.py line 281: self.total_steps = settings.max_steps or settings.max_epochs * self.steps_per_epoch (= 10 x 17,942 = 179,420 batches)
  • train.py lines 390-393: if not losses: self.skipped += 1; self.step += 1; return (a skipped batch never reaches the scheduler)
  • train.py lines 403-404: self.opt.step(); self.sched.step() (LambdaLR's counter advances only on real updates)
  • train.py line 314: progress = (step - warmup_steps) / max(1, total_steps - warmup_steps), where step is LambdaLR's counter
  • Real updates at the last logged step 179,300: 53,468; progress = (53,468 - 500) / (179,420 - 500) = 0.296; factor 0.5 x (1 + cos(0.296 pi)) = 0.799
  • Logged LR at step 179,300: 7.99e-4 = 80% of peak 1e-3; the configured schedule ('cosine to 0 over max_epochs x steps_per_epoch') would be ~1e-9 there
  • Only the epoch-based path is affected: with --max-steps, total_steps = max_steps and the stop rule also counts real updates, so that path is consistent
  • Warm-up is also stretched: 500 real updates spanned ~1,700 batches

Impact. A real bug: the run trained at near-peak LR throughout and never annealed. It plausibly contributes to the non-convergence and to the val_joint upticks at epochs 6 and 9 (0.4315 -> 0.4335, 0.3886 -> 0.3931), though this run cannot separate the schedule effect from the short training. The checkpoint is a valid but not final pretraining state.

I2high

Pretraining not converged after 10 epochs

  • val_joint per epoch: 0.6001, 0.5361, 0.4622, 0.4521, 0.4315, 0.4335, 0.4004, 0.3886, 0.3931, 0.3773; best = last epoch
  • Last-epoch gain vs prior best: 2.9%; change over the last 3 epochs: val_joint -5.8%, val_p1 -12.9%, val_p2 -20.8%
  • val_recon (-1.9%) and val_nce (-2.2%) are flat over the last 3 epochs; the remaining progress is in the physics heads
  • stop_reason = max_epochs, 13.345 h on a g4dn.xlarge (T4)

Impact. Downstream numbers come from an encoder that was still improving on its own objective; probes on a converged encoder may differ. Reconstruction and contrastive terms appear saturated, so more epochs mainly move P1-P3.

I3high

Most of the training data carries no self-supervised signal

  • Length scan of 5,071,584 train windows: 1 row 70.08%, 2-3 rows 13.35%, >= 4 rows 16.57% (24 rows: 293,922)
  • Losses need >= 2 rows (reconstruction) or >= 4 rows (min_rows_aux: contrastive, P1-P3), so 1-row windows produce no loss
  • Estimated batch mix: skipped 70.17%, reconstruction only 13.65%, all five losses 16.18% (1,075 logged real updates: 583 all-loss, 492 recon-only)
  • D14 length-bucketed batches put 1-row windows together, so whole batches are skipped rather than diluted

Impact. Only ~53.5k of 179,420 batches updated the model, and only ~29k trained the contrastive and physics heads. The time per epoch is spent partly on gathering windows that cannot train. The encoder has seen 1-row windows only through the embedding of other lengths, which matters because DataReplay and DoS test windows are almost all that short.

I4high

DataReplay and DoS windows are 1-3 rows (F11): the label-free score ranks them as more normal than benign, and length alone beats the model

  • Mean real rows on 1416 test: Benign 15.4, GridSybil 14.6, DataReplay 1.62, DoSRandom 1.24, DoSDisruptive 1.24
  • kNN anomaly AUROC vs benign (model / length-only): GridSybil 0.613 / 0.525, DataReplay 0.337 / 0.950, DoSRandom 0.144 / 0.965, DoSDisruptive 0.307 / 0.965
  • Flag rate at theta: DoSRandom 0.003, DoSDisruptive 0.045, DataReplay 0.077, below the benign rate 0.121
  • The memory bank is 60,000 unlabeled train windows, mostly DoS / DataReplay windows (manifest caveat), so short windows are close to the bank

Impact. With the current window unit and an unlabeled bank dominated by attack traffic, the anomaly score cannot detect 3 of the 4 attacks; 'unlike the train mix' is not 'unlike benign'. Reporting 1 - AUROC as a detector would be choosing the score direction from test labels and is not allowed (RULE 1). The window unit for DataReplay / DoS is the open decision in agent.md section 5.

I10high

No from-scratch control or frozen probes yet

  • src/runs/evaluation/all/T24/model-all/ holds only training_summary.json; results.json from scripts/evaluate_frozen_encoder.py is absent
  • pretrain_monitor bar for later probes: length-only AUC 0.531 on the check set

Impact. The central hypothesis (pretrained beats from-scratch under scarce labels) is untested; nothing in this report supports or refutes it.

I5medium

Window length is strongly encoded in z

  • Ridge probe recovers window length from z with R2 0.986 at init and 0.876 at epoch 10 (0.855-0.888 across epochs)
  • corr(|z|, length) = -0.647 at epoch 10
  • Length alone separates DataReplay / DoS from benign with AUROC 0.950-0.965 on 1416 test

Impact. Any supervised probe on z can reach high scores on DataReplay / DoS through length alone; probe results must be compared against the length-only baseline and reported separately for n <= 3 and n >= 4 before they count as evidence for the central hypothesis.

I6medium

Benign false-positive rate 0.121 at a threshold meant for 0.05

  • theta = p95 of 20,000 unlabeled train windows from check-set vehicles = 0.1868; benign_fpr_at_theta on full 1416 test = 0.121 (13,942 benign windows)
  • The calibration windows are the same attack-dominated, mostly 1-row train mix as the bank, while benign test windows average 15.4 rows
  • No validation split exists (D8'), so theta was not tuned (S1.4.4 / S2.2.2 require theta on val)

Impact. The threshold is calibrated on a population unlike benign traffic; the most likely cause is the calibration mix (length and class composition) rather than train-test drift, but this run cannot separate the two. Flag rates are not comparable to a 5% operating point.

I8medium

Single seed, single run

  • seed 0 only; one pretraining run of model-all
  • S1.4.1 acceptance requires >= 3 seeds

Impact. No variance estimate across pretraining seeds; differences of a few AUROC points (e.g. GridSybil 0.613 vs 0.525) cannot be called reliable.

I9medium

Test evaluation restricted to group 1416 (F14 open)

  • F14: 2.5-5.9% of GridSybil_0709 test benign identities have a near-copy in train within 1 m (8-10% within 3 m) under the vehicle-key split
  • Manifest scope: split test, group 1416, '0709 excluded until F14 is decided'; 116,634 test windows scored

Impact. Half of the test data is unused, and 0709 <-> 1416 transfer (S1.4.3, hypothesis H3) cannot be evaluated until F14 is fixed or documented.

I7low

Physics heads succeed on injected violations only

  • AUROC on injected violations in the check set: P1 0.489 -> 0.986, P2 0.462 -> 0.998, P3 0.513 -> 0.997
  • P1-P3 are trained and scored on violations we inject (D4, p = 0.5); real-data rules were label proxies or empty (F8)

Impact. Shows the pretext task is learnable and the heads work; says nothing yet about real attacks. It should not be presented as detection.

I11low

Run provenance gaps: GPU memory and model not logged, training tree was dirty

  • mem_gb is process RSS (host RAM, peak 11.52 GB); GPU memory is not logged on CUDA; env.json does not record the GPU model (T4 known only from agent.md)
  • env.json: git_commit b2ffd5a, git_dirty = true

Impact. The exact code that trained the checkpoint is not fully pinned by the commit, and GPU sizing for reruns has to be guessed. Checksums of all six run files verify (all_ok = true).

Roadmap

  1. Run npm run eval:all on the current checkpoint now: it costs no code and gives the first frozen-probe numbers against the random-init and length-only controls (X2).

  2. Fix the LR schedule with a test (X1), log GPU details (X9), and decide whether 1-row windows leave the SSL set (X3) before spending GPU time again.

  3. Decide the sequence unit for DataReplay / DoS (X4); without it, 3 of 4 attacks can only be separated by length.

  4. Add a vehicle-disjoint validation split (X5) and decide F14 (X8), both recorded as RULE 3 changes, so thresholds are tuned and both scenario groups can be tested.

  5. Rerun pretraining on the corrected setup with 3 seeds (X7) and repeat the frozen evaluation with length-split reporting (X6).

  6. Only then start few-shot fine-tuning and the memory-bank detector (S2, X10).

Limitations

  • All training numbers are pretraining health on the label-free check set (10% of train vehicles, 8,192 evaluation windows), not detection results.
  • The anomaly-score numbers use an untuned threshold (no validation split, D8') and a bank of unlabeled train windows that are mostly attack traffic.
  • Test covers scenario group 1416 only (116,634 windows); group 0709 waits on F14.
  • Benign test windows are pooled over the 4 families, which re-simulate the same traffic (F1), so benign windows repeat across families.
  • One seed, one run; the run used a learning-rate schedule that did not decay (I1) and stopped before convergence (I2).
  • Only attack codes A0 and A16-A19 exist locally; the full 19-attack VeReMi-Extension is not used.
  • No frozen-probe, from-scratch, Transformer or objective-ablation results exist yet.
