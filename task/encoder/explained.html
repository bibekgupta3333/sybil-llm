Section 1

The question in one picture

Cars send short status messages about once per second. Each message says "I am here, and I move this fast".

In a GridSybil attack, one attacker car sends messages under many made-up names. These names are "ghost" cars. The ghosts stand in a grid pattern, so a fake traffic jam appears.

A receiving car hears a stream of messages from each name. We cut a short piece of that stream. We call it a window. Then we ask one yes/no question:

The question: does this window come from a normal (benign) car or from a GridSybil ghost? The model turns the window into one score. A threshold turns the score into an answer.

This page covers a small baseline model. It is not the main TimesNet model of the thesis. We ask two things:

  • Can a small neural network tell the two kinds of windows apart?
  • Does it do better than simple shortcuts?

Section 3

The data: links and windows

  • A link = all messages one receiving car heard from one sender name (a pseudonym), in time order.
  • Long links are cut into pieces of at most 64 messages. Example: a 150-message link gives windows of 64, 64 and 22 messages.
  • Each message becomes one row of 13 numbers (the features). So a window is a table of 64 rows × 13 columns.
  • Short windows are filled up with empty padding rows. A mask says which rows are real (1) and which are padding (0).
  • On average of all rows are padding. So the mask matters a lot.

    The 13 features in plain words

    • "Claimed" = what the sender writes in its message. An attacker can lie here.
    • "rx" = the receiving car's own sensors. We trust these.
    • Positions are in metres on the simulated map.
    • Every feature is standardised: we subtract the train average and divide by the train spread (standard deviation). So "0" means "average".

    How many windows, and how they are split

    We split into train and test by sender vehicle:

    • About 90% of vehicles go to train, 10% to test.
    • No vehicle is on both sides.
    • Why? Windows of the same car look alike. If one car were on both sides, the test would partly check memory, not skill.

    Inside train we keep a validation set apart: 10% of the train sender vehicles (seed 0, the same for every run). The model never learns from these windows. We use them only for two things: to decide when to stop training, and to set the threshold.

    Section 4

    Two models, one encoder

    Both models start with the same encoder. The encoder is a small network. It squeezes a whole window (64 × 13 numbers plus the mask) into 16 numbers, called z. Think of z as a short summary of the window. The two models differ in what comes after the encoder.

    (a) One-class autoencoder benign only

    • Trained on benign windows only. Its job: rebuild its own input.
    • So it learns what "normal" looks like.
    • A window it rebuilds badly does not look normal. We flag it.
    • Training needs no attack labels. This is the real-life case: new attacks have no labels.

    parameters = encoder 36,656 + decoder 43,533.

    (b) Supervised encoder + head benign GridSybil

    • Trained with labels (benign = 0, GridSybil = 1).
    • It outputs the probability that a window is GridSybil.
    • The head is tiny: Linear 16 → 32, ReLU, Linear 32 → 1.
    • It sees attack labels, so it is an upper bound. It shows how well this encoder could do. It does not show how well a label-free detector does.

    parameters = the same encoder 36,656 + head 577.

    Both models also give a second score from z alone: the Mahalanobis distance. It asks: "is this summary far from the usual benign summaries?" Section 9 explains it.

    The words Conv1d, kernel, stride, BatchNorm, ReLU and ConvTranspose1d are explained just below, next to the picture.

    width = time steps, height = channels

      Words used in the picture

      Channel. One number per time step. The input has 14 channels: the 13 features plus the mask. The mask tells the network which rows are real. Padding rows are set to 0 before the encoder.

      Conv1d (1-D convolution). A small sliding filter, the kernel. It looks at 3 neighbouring time steps at once. It mixes all channels into new ones. The same kernel is used at every position. So it finds a short pattern wherever it appears in time.

      In the layer names: k3 = kernel size 3. s1 / s2 = stride 1 / 2. 14→32 = 14 channels in, 32 out.

      Kernel 3, stride 2: the kernel jumps 2 steps each time. So the output is half as long (8 → 4 here; 64 → 32 → 16 in the model). One padding cell at each end keeps the edges.

      BatchNorm (BN) + ReLU. BatchNorm rescales each channel to a steady range. This makes training smoother. ReLU keeps positive values and sets negative ones to 0. It lets the network learn curved (non-linear) relations.

      Flatten + Linear. The 64 × 16 block is laid out as one list of 1,024 numbers. A fully connected layer maps it to 16 numbers.

      Bottleneck and z. z has only 16 numbers. The window holds 64 × 13 = 832 feature values. So the network cannot just copy the window through. It must keep only the most useful patterns. This narrow point is the bottleneck.

      ConvTranspose1d. The decoder's "reverse convolution". With kernel 4 and stride 2 it doubles the length (16 → 32 → 64). A last Conv1d maps 32 channels back to the 13 features.

      Section 6

      The loss functions

      A loss is one number that says how wrong the model is. Training changes the weights to make it smaller. Each model has its own loss.

      Autoencoder: masked mean squared error (MSE)

      1. For every real row and every feature, take input minus copy.
      2. Square it. Now minus and plus errors both count, and big errors count a lot.
      3. Take the average.

      Padding rows are skipped. They hold no information. About 71% of rows are padding, so they would control the loss if we kept them.

      toy example: 4 rows × 2 features (f1, f2), made-up numbers
      rowinputcopyerror²mask
        • In the real model we use all real rows and all 13 features.
        • In training, the loss of a batch uses the real rows of all its windows together.
        • The score of one test window is the same formula on that window alone. We also keep it per feature (Section 10).

        Supervised model: weighted binary cross-entropy (BCE)

        The head outputs a probability p between 0 and 1 that the window is GridSybil. (A sigmoid squeezes any number into that range.) Binary cross-entropy is

        loss = − [ w · y · log p + (1 − y) · log(1 − p) ]

        Here y = 1 for GridSybil and 0 for benign.

        • If the true class gets probability near 1, the loss is near 0.
        • If the model is sure and wrong, the loss grows without limit (see the curve).

        Why the weight w? The fit set has more GridSybil than benign windows ( windows, 196,923 GridSybil). Without a weight, the model could score well by leaning towards "GridSybil". The code sets w = benign / GridSybil = 0.5475. So each GridSybil window counts about half. Both classes then carry the same total weight.

        Loss for one window, against the probability the model gives to its true class. Example: a benign window with p = 0.9 GridSybil costs −log(0.1) ≈ 2.30. A GridSybil window with p = 0.9 costs 0.5475 × −log(0.9) ≈ 0.058.
        Section 7

        Training

        The training set is shuffled and cut into batches of 256 windows. For each batch the computer repeats one cycle:

        1. Forward: run the batch through the model.
        2. Loss: compare the output with the target. (The AE's target is the input itself. The supervised model's target is the label.)
        3. Backward: for every weight, compute how the loss would change if the weight moved a little. This is the gradient.
        4. Update: the Adam optimiser moves every weight a small step downhill. The step size is the learning rate (start ). Weight decay keeps weights small.

        One pass over all batches is an epoch. After each epoch we measure the loss on the validation windows. The model never trains on them.

        one training step

          Loss going down (autoencoder, seed 0)

          validation losstrain lossbest epochlearning rate halvedearly stop
          LR halved after epochLR old → newLast best epoch

          LR = learning rate. Each drop comes after 4 epochs in a row without a real improvement. ("Real" = better by more than 0.01%. This is the rule of PyTorch's ReduceLROnPlateau. So a tiny new best does not reset its count.)

          Stopping at the right time

          If a model trains too long, it starts to memorise the training windows. This is overfitting. You see it when train loss keeps falling but validation loss stops falling or goes up. Two rules watch the validation loss:

          • Lower the learning rate: if validation loss has not improved for more than epochs (so on the 4th), halve the learning rate (×). The steps become finer.
          • Early stopping: if it has not improved for epochs, stop. Keep the weights from the best epoch.

            Why is AE train loss above validation loss at first?

            • Seed 0: this happens only in epochs 1–6, 8 and 11. After epoch 11, train loss is always below, as usual.
            • The train number is an average taken during the epoch. The weights still improve fast then, so the bad early batches pull it up.
            • The validation number is measured once, at the end of the epoch.
            • BatchNorm also works a little differently in training mode. And the two losses come from different vehicles.
            • Note: MSE and BCE are on different scales. Do not compare the two charts with each other.

            Is there overfitting? AE: no clear sign. Validation loss flattens and never goes up much. Supervised: a little. Its validation loss is lowest at epoch (seed 0) and then rises while train loss still falls. Early stopping catches this and keeps the best weights.

            Section 9

            From score to decision

            After training, every test window gets a reconstruction error (its masked MSE). Higher error = less like the benign windows the AE learned.

            To get a yes/no answer we need a threshold. A window is flagged as GridSybil if its error is at or above it.

            We choose the threshold without any attack data:

            • It is the 95th percentile (or the 99th) of the errors on the benign validation windows.
            • A percentile is a cut-off. 95% of benign validation errors are below the 95th percentile.
            • So by design about 5% (or 1%) of benign windows are flagged by mistake.

              RecallOf all GridSybil windows, the share we flag (detection rate).

              What it means (honestly)

              The one-class AE learned something real, but not much.
              • AUROC is clearly above the length shortcut (). The intervals do not overlap.
              • It gets better with longer windows: for ≤ 3 messages, for 49–64 (3-seed mean).
              • At the p95 threshold it catches only of GridSybil windows (3-seed mean).
              It loses to simple statistics. Stats + LR () beats the AE in every length group. To be fair: stats + LR uses labels, so it is not one-class. But it is a much cheaper model.
              With labels, the same small encoder works well.
              • AUROC . F1 at probability 0.5. (Both 3-seed mean.)
              • Best in every length group. The gap is largest on 1–3-message windows ( vs for stats + LR).
              • So the network can show the difference. Learning only to rebuild benign windows does not find it.
              • This is the upper bound, because it uses labels.
              The AE's Mahalanobis score is inverted (, below 0.5 in every seed and every length group).

              Section 12

              Next checks

              1. Relative features only. Train again without absolute positions. Keep speeds, accelerations, range, bearing and time gaps. If the scores drop a lot, location did the work. If not, the models read motion.
              2. Choose the Mahalanobis direction on validation only. Decide "far" or "near" = suspicious with validation data (for example a small labelled validation set, never test). Then score the test set once.
              3. More seeds and other z sizes. Repeat with more seeds, and with z of 4, 16 and 64 numbers. Does a narrower or wider bottleneck change what the AE learns?
              Section 13 · practice

              Questions you may be asked — with short answers

              Why train only on benign windows?
              In real life a new attack has no labels. A model that only learns "normal" can still flag what does not fit. So the AE never sees GridSybil while it trains.
              What does the loss measure?
              For the AE: the average squared difference between a window and the AE's copy of it (masked MSE). Lower = better copy. For the supervised model: weighted BCE, which is small when the true class gets a high probability.
              Why is padding ignored?
              Padding rows are empty fill-up rows with no information. About of rows are padding. If we kept them, they would control the loss and the score.
              What is early stopping?
              We stop when validation loss has not improved for epochs, and keep the best weights. Seed 0 stopped at epoch and kept epoch .
              Why lower the learning rate?
              When progress stops, big steps jump over the best point. Smaller steps can still find small gains. The rate halves on the 4th epoch without progress. For seed 0 it went from down to 0.00003125 in 5 steps.
              Is the model overfitting?
              The AE: no clear sign. Validation loss flattens and does not rise over time. The gap to train loss stays small. The supervised model overfits a little after its best epoch, and early stopping stops it.
              What is z?
              z is the 16-number summary of a window that the encoder makes (the "latent" vector). The decoder rebuilds the window from z alone. In a 2-D picture, the AE's z does not separate the two classes. The supervised z does.
              Why is the latent (Mahalanobis) score below 0.5?
              GridSybil windows more often have z values closer to the benign centre than benign windows. So "far = suspicious" points the wrong way (AUROC , 3-seed mean). We do not flip it, because that would use the test labels.
              Why does the AE lose to simple statistics?
              The stats model is trained with labels, so it learns directly what separates the classes. The AE only learns to copy benign windows. GridSybil windows get higher errors, but the two error ranges overlap a lot (median error 0.0745 benign vs 0.147 GridSybil, seed 0).
              Is the supervised model a fair comparison?
              No, and it is not meant to be. It uses attack labels, so it is an upper bound. It shows that the encoder can separate the classes when it is told how.
              Could the model learn location instead of motion?
              Maybe. Absolute positions are inputs. The errors of range and claimed_pos_y separate the classes best. We have not tested it. The next check is to train without absolute positions.
              Why three seeds?
              A seed fixes the random start and batch order. Three seeds show if a result is stable. AE AUROC is / / (seeds 0 / 1 / 2), std . So it is stable.
              What would you try next?
              Train without absolute positions. Choose the direction of the Mahalanobis score on validation data only. Try more seeds and z sizes of 4, 16 and 64.

              We train a small autoencoder on benign windows only and use its error as a GridSybil score. The talk goes through nine stages, from data quality to how much we can trust the numbers.

              Stage 1 · Before trainingData quality

              Window = 64 messages × 13 features + mask. Standardised with train-only statistics.

              Split 90 / 10 by sender vehicle. AE: fit , validation benign.

              Test: benign, GridSybil. No labels or sender IDs as inputs.

              The model sees only the 13 message features and the mask, never a label or a sender ID. Train and test never share a sender vehicle, so the test checks skill, not memory.

              Stage 2Encoder architecture

              Three convolutions, kernel 3, stride 1 / 2 / 2, each with BatchNorm + ReLU.

              Stage 3Forward pass: z = fθ(X)

              The encoder f, with weights θ, turns a window X into z (16 numbers).

              The decoder turns z back into a copy X̂.

              9 steps: convolution, stride, flatten, matrix × vector, decoder.

              This animation follows one window through every layer with the real sizes. The key step is the matrix times vector product that turns 1,024 numbers into the 16 numbers of z.

              Stage 4Training: X → z → X̂ → loss

              Masked MSE on real rows only.

              Backpropagation computes the gradients. Adam updates the weights.

              lr · weight decay 1e-5 · batch · at most epochs

              One training step is: take a batch, rebuild it, measure the masked error, compute gradients, and move every weight a small step. Padding rows never count in the loss.

              Lesson: the training goal must match the detection goal.

              The autoencoder is good at its own task, rebuilding benign windows, but that skill only partly helps to find GridSybil. The same encoder trained for the detection goal reaches 0.928, so the goal matters more than the architecture.
